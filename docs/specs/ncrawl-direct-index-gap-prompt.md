Goal: raise the number of direct (employer-own career system) jobs we can offer to Google, from about 204,000 to as close to all 352,000 as the employers' own sites allow. Dry run first; do NOT import into production until the owner approves the counts.

Why
- A job page is offered to Google only when it is on the employer's own career system AND the crawler last confirmed it open within 14 days AND its stored description is 1,500 bytes or more (`PUBLIC_JOB_VERIFIED_DAYS`, `PUBLIC_JOB_MIN_INDEX_DESCRIPTION`, `src/lib/jobs/public-job-page.ts`). Do not change those rules in this task.
- Measured 2026-11-13 from a 10% block sample of live jobs (full numbers in `docs/jobs-report/direct-index-gap-2026-11-13.md`, query `scripts/jobsreport/direct_index_gap.sql`). Of about 352,000 live direct jobs, about 204,000 (58%) are offered. The rest:
  - about 82,000 (23%) have good text but were last confirmed open 14 to 30 days ago. The crawler holds the row and has not re-checked it in time. Nothing is older than 30 days, because the board hides those.
  - about 39,000 (11%) have NO description stored at all (null).
  - about 26,000 (7.5%) have a description under 1,500 bytes. `docs/specs/ncrawl-full-description-prompt.md` already covers the stubs at RTX, BAE, Oracle, HPE, Marsh, Trane, PNC, Cisco and others; this task adds the null-description rows, which are a different failure.
  - Of the 65,000 with missing or short text, about 45,000 were confirmed open in the last 14 days, so they become offerable the moment the text is stored.
- The server does not drop text: `src/app/api/admin/jobs/import/route.ts` stores what the sender posts, and a payload with no description never erases one already held. The fixes are in the crawler.
- Method rule (CLAUDE.md "Employer discovery rule"): read the career site and the job system behind it, never the corporate site. Keep the polite rate and the identified user agent.

Do this, in order

Propose a cadence that keeps every direct row inside 14 days, and its request cost. A row the employer no longer lists should close through the normal liveness path, not be kept alive.
